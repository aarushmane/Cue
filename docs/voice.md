# Interruptible voice and scene control

FastAPI owns the voice transport and ElevenLabs integration through one persistent `/ws/voice` connection. React owns microphone capture, audio playback and immediate movement interruption. Next retains the existing TypeScript scene planner and its grounded agent tools. The socket delegates scene requests to `/api/wayfinding/voice` internally; the duplicate Next voice HTTP endpoints have been removed.

## Setup

Set `ELEVENLABS_API_KEY` in `.env.local` for speech and `GEMINI_API_KEY` or `ANTHROPIC_API_KEY` for reasoning. `npm run dev` starts both servers. Restart the backend after changing its environment settings. `NEXT_PUBLIC_BACKEND_URL` defaults to the current hostname on port 8000; `SCENE_SERVER_URL` defaults to `http://127.0.0.1:3000`. `ELEVENLABS_VOICE_ID` defaults to George and `ELEVENLABS_TTS_MODEL` to `eleven_flash_v2_5`.

Click the microphone to start. “Require Hey Cue” is enabled by default for noisy rooms: say “Hey Cue” followed by each request. Each wake phrase opens one request; submission closes that window while keeping the microphone session connected. An incomplete request expires after eight seconds without accepted speech, with a fifteen-second maximum, and reports an actionable error. Scribe receives “Hey Cue” and “Cue” as keyterm hints. Transcript spellings “hey queue”, “hey Q”, “hey kew” and “hey que”, punctuation and joined “HeyCue” are accepted. If Scribe commits “Hey” separately, the next segment can complete the wake phrase within 2.5 seconds. Unaccepted room speech does not replace the displayed command. A find request draws a route; the move tool is intended for explicit movement requests. This uses a stored scan and its catalog/geometry, rather than continuous live scene vision.

Bottom-left settings selects voice and speed, previews speech without microphone access, and switches spoken responses, wake-word prompting and spoken directions. Preferences stay in this browser. Voice lists and previews use the same backend socket. Missing Voices: Read permission falls back to published voices and direct voice IDs; it does not mean transcription or TTS is unavailable.

| Control | Behavior |
| --- | --- |
| Microphone | Starts/ends the session and live transcription. |
| Square | Stops pending reasoning, output audio and simulated movement immediately; keeps listening. |
| Play | Replays the latest response during an active session. |
| Escape | Same immediate interruption as Square. |
| “Hey Cue” | Opens one request and interrupts pending work, speech or motion. The microphone stays connected between requests. |
| Start speaking, request window open | Accepted partial transcripts collect the request and stop movement. During reasoning or playback, say “Hey Cue” or Stop to interrupt; other speech is ignored. Microphone volume alone does not cancel work. |
| “Stop”, “wait”, “pause” | Stops immediately and acknowledges without invoking an LLM. |
| “Hey Cue, resume” | Replans directly to the saved item ID from the latest position; no destination search or model call. |
| “Hey Cue, turn left/right/around” | Changes the simulated viewpoint through bounded scene commands. |

## Data flow

1. An explicit click requests one microphone stream, with echo cancellation and noise suppression. Web Audio analyses it locally for the waveform.
2. A `token` command on `/ws/voice` exchanges the server-only master key for a single-use Scribe token. WebSocket origins and command rates are checked. Authentication has not been added.
3. A same-origin AudioWorklet packs 100 ms of 16 kHz mono PCM16 per message. The official ElevenLabs SDK sends those packets over its realtime Scribe websocket. The microphone is never monitored through the speakers.
4. Scribe uses background-audio filtering, supplies partial transcripts and commits after 0.9 seconds of silence. The browser combines adjacent commits and waits a further 1.4 seconds without an accepted partial before submitting one complete request. Incomplete openings such as “can you find me” and trailing word fragments remain pending until more speech arrives or the request window expires. Stop bypasses this delay. A `turn` includes current position, normalized heading, measured walking speed, destination ID and eight recent messages. History resets when the microphone session ends. Wake and work gating are transcript-based: enabled microphone audio still goes to ElevenLabs while waiting for activation and during playback, so intentional spoken interruptions remain available.
5. Saved catalog matches, resume, direction requests, basic turns and speed adjustments bypass the LLM. Matching requires full query coverage: a named product cannot silently fall back to its category. A new destination missing from the catalog returns a catalogue miss immediately, without image downloads or model calls. Only an explicit request such as “search the photos for pineapple” or “check the photos” starts a targeted photo search, with exact-product verification before routing. Conversation uses a small LangChain tool agent, without Deep Agent filesystem/planning tools. Its tools read pose/route, adjust orientation, change speed, find/plan, move and stop. Progress, paths and adjustment actions stream over the same socket, and are accepted only by the active browser turn. Search/route tools memoize their results within each run instead of repeating expensive work.
6. A `speak` command streams ElevenLabs 24 kHz PCM over binary socket frames. The browser schedules buffers as bytes arrive; an output analyser drives the waveform. Commands carry request ids, so cancelled audio and late results can be discarded independently.
7. Pose telemetry streams to FastAPI four times per second; it does not invoke a model or consume the command rate limit. The `read_position` tool can fetch the latest per-connection state during a turn. While navigating, a 750 ms local loop computes cues using live floor position, heading and speed, with speed-dependent look-ahead. Cues are deduplicated and spaced at least four seconds apart. The simulation aligns before walking, pauses translation for sharp turns, and faces the locked product at arrival. Arrival is announced once walking and final turning finish. No continuous photo searches or model calls run in the background. Disabling spoken directions or responses silences cues.

The visitor can walk themselves while voice guidance follows the selected destination. Up/Down or W/S move forward/backward, Left/Right turn, A/D move sideways, and dragging changes the view. Manual walking is included in live movement telemetry and replans the path from the current floor position. Movement keys and scene interaction do not cancel speech or a pending voice search. Automatic guidance speech does not require another wake phrase, and arrival waits for the current response to finish instead of cutting it off. Voice movement commands are not needed for this flow.

## Cancellation

Every accepted command invalidates the previous turn's `AbortSignal`, stops scheduled audio locally, and sends a socket `cancel` for its request id. FastAPI cancels the associated async provider/planner task. Late results are discarded, so they cannot restart movement. Provider work already accepted may still be billed. Keeping a socket open reduces setup and centralizes cancellation; model/tool latency still determines much of the response time.

Stop leaves the microphone connected but settles the waveform into a thin muted line and highlights Square. Mic off uses a dotted baseline. A new accepted command or Replay restores measured waveform motion. These states are separate from disabling spoken responses in settings.

Between requests, only the wake phrase and explicit Stop are accepted by default. During reasoning, playback and a one-second echo tail, those same explicit commands are required to interrupt, even if wake-word prompting is off. Other speech is ignored through its final commit, including delayed commits after work ends. A wake phrase opens a new request immediately. Accepted partials can stop movement while collecting that request; raw microphone volume never cancels a turn. A conservative text comparison also suppresses likely echoes of the recent output. Ignored echoes do not cancel a queued request's submission timer, and final transcripts are re-evaluated if an earlier partial was rejected outside active work. Guidance waits while a request is being collected so it cannot discard a partially assembled sentence. These gates and ElevenLabs background filtering reduce unwanted room speech; they are not speaker identification. Deliberately saying Stop remains an interruption without a wake phrase, so a nearby person saying Stop can still interrupt. Real microphone trials across rooms and speaker setups are needed to assess acoustics. The commit grace period intentionally adds latency to avoid acting on unfinished sentences.

New product requests bypass conversation history when catalog matching or photo search can handle them directly. Common requests such as “can you help me find” and “do you have” are normalized to the requested product. Conversational search tools are pinned to the current request unless it explicitly refers to the existing route; failed photo searches produce a grounded response naming the current request. Brand-only catalog matches include a matching product alias in the returned label, for example “Matador Beef Jerky”.

The Three.js simulation stops guidance, turning and held movement keys synchronously. Matterport cancels the movement queue and calls `Camera.stop()` when supported by the connected SDK; older embeds may finish the transition already in progress. The photo fallback uses discrete scan-point jumps; interruption prevents subsequent jumps. An already applied jump is not reversed. Resuming is an explicit new request, avoiding surprise movement when someone pauses mid-sentence.

The browser controls immediate interruption and execution; the existing scene agent handles language and grounded geometry tools. LangGraph's human-in-the-loop `interrupt()` is a checkpoint mechanism, distinct from stopping audio or camera motion.

## Verification

Automated test suites and browser test tooling were removed at the user's request. Keep verification lightweight. A manual voice check can cover microphone start/stop, “Hey Cue” interruption, voice selection and preview, muted responses, and directions while navigating. Live Gemini tool selection and a short ElevenLabs TTS call were previously checked; real microphone trials are needed to assess acoustics and wake-word recognition quality.

## Catalog and deployment

Interactive search reads saved JSON and never builds a full catalog on demand. `npm run wayfinding:catalog -- <modelId>` explicitly prepares/saves the catalog before deployment. Typed and voice catalogue misses never automatically rescan the images. Explicit photo searches share in-flight work per scan and normalized product; verified results are cached for 30 minutes and completed misses for two minutes. Cancelling the last waiting request aborts image downloads and provider calls. Timeouts and unavailable searches are evicted rather than cached as missing products. Photo searches have a 20-second budget; scene requests have a 25-second budget, with a 30-second browser fallback that reports an actionable error.

No database is required for the current read-only application. Include `data/wayfinding/*.catalog.json` in the deployed Next server; serve large images/meshes from object storage or a CDN and keep API keys on the servers. Deploy FastAPI on a host supporting persistent WebSockets. Set `NEXT_PUBLIC_BACKEND_URL` to its HTTPS URL, `SCENE_SERVER_URL` to the Next server URL, and `BACKEND_CORS_ORIGINS` to the frontend origin. `VOICE_BACKEND_URL` optionally overrides the server-to-server pose URL. In-memory connection state belongs to its FastAPI worker; use a single worker initially or shared ephemeral state/sticky routing when scaling. A database is only needed for editable inventory, persistent sessions or user data.
